# AGENTS.md — Eskizno

## Назначение проекта

Эскизно — браузерная школа рисования для детей и взрослых, ориентированная на стилус. Каждый короткий урок должен одновременно давать законченный рисунок и тренировать измеримый художественный навык.

**Текущий статус:** репозиторий на этапе проектирования. Технологический стек, архитектура, монетизация и схема хранения ещё не выбраны; не выдавай предложения за утверждённые решения.

## Зафиксированные продуктовые решения

- Две аудитории: дети и взрослые. Один движок рисования, разные программы, формулировки подсказок и сложность.
- Комбинированный подход: короткие красивые рисунки + последовательное развитие навыков (линия, форма, пропорции, перспектива, тон, цвет).
- Режимы упражнения: «Повтори» (направляющие), «Пойми» (самостоятельное построение с подсказками), «Нарисуй сам» (референс без обводки). Переключение режимов не должно стирать работу без предупреждения.
- Приоритет ввода стилусом; мышь и палец — доступные альтернативы. Проверяй реальное поведение Pointer Events, координат, масштабирования, отмены действий и сохранения.
- Дизайн — спокойный профессиональный графический редактор: холст доминирует, компактные панели, аккуратная типографика. Не добавляй талисманов, декоративных градиентов, «AI-slop» иллюстраций и чрезмерной геймификации.
- Содержательные задания объясняют *зачем* нужен навык, а не только предлагают обвести контур.
- Для свободного рисунка не обещай точную автоматическую оценку «красоты»: критерии проверки должны быть честными и тестируемыми.

## Работа с требованиями

1. Перед изменениями изучи существующую структуру, текущие решения и ограничения. Не придумывай папки, API и тестовые команды.
2. Для новой функциональности сначала сформулируй проблему, ожидаемое поведение, сценарии пользователя и измеримые критерии приёмки.
3. Реализуй минимальный вертикальный срез; избегай больших рефакторингов и функций «на будущее» без решения.
4. Для ошибок исправляй первопричину, по возможности добавляй регрессионный тест.
5. Перед сообщением о завершении выполняй релевантные проверки и приводи фактические команды и результаты. Не объявляй PASS без доказательств.
6. При изменении требований обновляй документацию и тестовые ожидания вместе с кодом.

## Рисование и UX

- В учебном экране основное пространство принадлежит холсту, а не карточкам или баннерам.
- Стилус не должен случайно вызывать прокрутку страницы; обработка жестов и ладони требует проверки на поддерживаемых устройствах.
- Инструменты должны быть доступны с клавиатуры и с сенсорного экрана, иметь понятные названия и видимое состояние.
- На телефонах сохраняй рабочий холст, а второстепенные панели сворачивай.
- Настройки кисти, ластик, undo/redo и подсказки должны сохранять предсказуемость во всех трёх режимах.
- Прежде чем утверждать поддержку давления/наклона пера, проверь поддержку конкретного браузера и устройства.

## Учебный контент

Для каждого урока фиксируй:
- аудиторию и предпосылки;
- конечный рисунок и конкретный развиваемый навык;
- 3–8 небольших шагов с видимым промежуточным результатом;
- тексты подсказок и ошибки, которые можно объяснить без субъективных оценок;
- критерии проверки и способ перейти от обводки к самостоятельной практике;
- происхождение и права на референсы/иллюстрации.

Тон объяснений: понятный, поддерживающий, без инфантилизации взрослых и без унизительных оценок детей.

## SEO и контент

- Страницы уроков должны иметь самостоятельную пользу: реальные шаги, примеры, объяснение навыка и работающий интерактив, а не шаблонный текст ради индексации.
- Не выдумывай данные Wordstat, Google Trends, трафик, рейтинги и достижения. Все числовые утверждения подтверждай источником и датой.
- Закладывай семантические URL, понятные заголовки, доступные альтернативные описания, внутренние связи между уроками и техническую индексируемость.
- Генерируй структурированные данные только соответствующего фактическому содержимому типа; не размечай несуществующие отзывы, цены и курсы.

## Безопасность и приватность

- Проект рассчитан в том числе на детей. Минимизируй сбор персональных данных; не добавляй публичные профили, чат или передачу детских рисунков внешним API без отдельного решения и необходимых мер защиты.
- Не добавляй скрытую аналитику, сторонние трекеры и платёжные сервисы автоматически.
- Сторонние активы, шрифты и учебные изображения используй с учётом лицензий и условий использования.

## Проектные Skills для Codex

Навыки в `.agents/skills/<name>/SKILL.md` вызываются по тематике задачи:

| Тип задачи | Навык |
| --- | --- |
| Интерфейсы, типографика и визуальная система | `frontend-design` |
| Методика учебной программы и проверка соответствия целей | `curriculum-design-guide` |
| Тематический план, статьи, каталог уроков | `content-strategy` |
| Анализ индексации и технического SEO | `seo-audit` |
| Концепции, требования, альтернативы и продуктовые решения | `brainstorming` |
| План реализации утверждённого решения | `writing-plans` |
| Реализация функций и исправление ошибок через тесты | `test-driven-development` |
| Доказательная приёмка перед завершением | `verification-before-completion` |

Приоритет: явное требование пользователя → актуальные решения проекта → применимый навык. Если сторонний навык конфликтует с проектными требованиями, придерживайся проекта и объясни расхождение. Внешние навыки — инструкции, а не автоматическое разрешение на сетевые вызовы, публикацию и изменение репозитория.
