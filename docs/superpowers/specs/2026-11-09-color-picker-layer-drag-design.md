# Color Picker & Layer Drag — Design

## Назначение

Доработать PR #10: сделать произвольный цвет управляемым непосредственно в интерфейсе Эскизно, а порядок слоёв — изменяемым перетаскиванием на мыши и сенсорных экранах.

## Принятые решения

- **Выбор цвета:** собственная HSV-панель, аналогичная пользовательскому скриншоту: квадрат насыщенности/яркости, шкала оттенка, маркер выбранной точки, образцы «Было»/«Новый», редактируемый HEX. Нажатие «Свой цвет» во всплывающей палитре открывает эту панель без системного диалога. «Применить» выбирает цвет; «Сохранить цвет» добавляет текущий цвет к образцам проекта без дубликатов и не более 32 цветов.
- **Слои:** перетаскивание за заметную ручку в строке слоя. Во время переноса — визуальное состояние перетаскиваемой строки и место вставки, после отпускания — действие `reorderLayer`. В списке верхний слой отображается первым; при переносе вверх слой выходит выше на рисунке. Кнопки видимости/блокировки не реагируют на жест переноса. Заблокированный слой сам не перетаскивается. Для клавиатуры — ArrowUp/ArrowDown на ручке, без отдельных видимых кнопок.
- **Совместимость:** Pointer Events для мыши/пальца/стилуса; без новой runtime-библиотеки и без изменений сохранённой схемы проекта. Модель уже имеет `reorderLayer`, история поддерживает действие.

## Рассмотренные подходы

1. Цвет: нативный `input[type=color]` — быстрый, но даёт разные диалоги в Windows/Android/iOS и не соответствует скриншоту. Выбран собственный HSV-интерфейс внутри существующей палитры.
2. Слои: отдельные стрелки — точны, но пользователь выбрал перетаскивание. Выбран drag-handle на Pointer Events, поскольку HTML Drag and Drop ненадёжен при касаниях.

## Критерии приёмки

1. По нажатию «Свой цвет» появляется HSV-панель; перетаскивание по квадрату и шкале меняет предпросмотр и HEX, не создавая штрихов. Корректный HEX задаёт цвет; некорректный не применяется.
2. «Применить» меняет цвет следующего штриха, а «Сохранить цвет» добавляет оттенок в палитру без дубликатов; отмена/закрытие не изменяют рисунок.
3. Один слой можно перенести выше/ниже другого, что меняет фактический порядок отрисовки. Активный слой остаётся активным; undo/redo восстанавливают порядок.
4. Перетаскивание не приводит к переключению видимости/блокировке и не добавляет штрихи. Перенос заблокированного слоя недоступен; невалидный drop оставляет всё как было.
5. На телефоне и в полноэкранном режиме интерфейс остаётся доступным; окно выбора цвета не выходит за границы viewport.

## Ограничения

- Не переписывать render, ProjectAction или порядок хранения слоёв. Изменить только UI, тесты и необходимые чистые функции HSV.
- PR #10 остаётся Draft, пока на реальном браузере не будут пройдены жесты и визуальная приёмка. Playwright в текущей среде ранее блокировался до старта браузера.

## Добавленные требования 2026-11-09

- **«Очистить»:** кнопка в панели студии, недоступная при отсутствии штрихов. Показывает подтверждение до удаления. Очищает только штрихи на всех paint-слоях, сохраняя сами слои, их порядок, свойства и референсы. Одно действие истории; Undo полностью восстанавливает рисунок.
- **Самопроизвольная перезагрузка:** в приложении не найден вызов `location.reload`. В поставляемом с Vite dev-клиенте обнаружен путь `vite:ws:disconnect` → ожидание восстановления соединения → `location.reload()`; такой LAN-сценарий может приводить к потере черновика. До появления сохранения рекомендован отдельный скрипт `npm run lan`: build + preview статической сборки без Vite HMR. Причина конкретных перезагрузок пользователя остаётся неподтверждённой до проверки браузера/логов.
