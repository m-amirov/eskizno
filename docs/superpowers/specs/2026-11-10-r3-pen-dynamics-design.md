# Эскизно — R3A: нажим, наклон и динамика кистей

**Дата:** 2026-11-10

**Статус:** на утверждение; код R3A не реализован

**База:** `feat/r2-selection-transform` / Draft PR #17 (включая исправление мобильного импорта)
**Решение по этапности:** пользователь выбрал вариант A — малые последовательные PR вместо полного R3 одним изменением.

## 1. Зачем и что получит художник

В свободной студии художник с совместимым стилусом сможет делать более живые линии: толщина реагирует на нажим, а угол каллиграфического пера — на наклон. При рисовании мышью или пальцем результат должен остаться привычным. Созданный штрих можно отменить, трансформировать, сохранить, открыть снова и экспортировать без потери динамики.

В обучении те же реализованные кисти работают через существующую политику доступа к инструментам. Настройки динамики не должны открывать заблокированный уроком инструмент.

Этот этап **не** обещает подтверждённую поддержку конкретного Huawei/Яндекс Браузера без проверки физическим пером.

## 2. Варианты и выбранная граница

| Подход | Компромисс | Решение |
| --- | --- | --- |
| **A. Последовательный R3**: сперва данные пера и выразительные кисти, затем маски и наложение | Каждый PR независимо тестируется; сложные маски отложены | **Выбран** |
| B. Весь R3 сразу: нажим, наклон, маски, наложение | Одна большая миграция и трудно локализуемые регрессии | Отклонён |

**R3A в одном отдельном PR:** новые точки пера в документе, совместимая миграция, ограниченная динамика существующих кистей, компактные настройки, тесты и диагностический протокол физической приёмки.

**После R3A отдельными решениями/PR:** маски, режимы наложения, расширение динамики на остальные пресеты, произвольные пользовательские кисти, стабилизация линии, если будет подтверждена необходимая задержка/производительность.

## 3. Ограничения из текущего кода

- `apps/web/src/editor/model.ts`: `DOCUMENT_SCHEMA_VERSION = 2`, `Point = {x,y}`, `Stroke.points: Point[]`; валидатор и `copyStroke` явно копируют только координаты.
- `EditorCanvas.tsx`: `pointerSamples` читает `getCoalescedEvents()`, но сохраняет только координаты; `appendDistinctPoints` считает идентичными образцы с одинаковыми `x,y`. Есть защита от параллельного pen/touch и от двухпальцевого масштабирования.
- `brushes.ts`: десять пресетов и детерминированная отрисовка Canvas2D; семплинг ограничен `MAX_STAMPS = 2600`.
- `render.ts`: штрихи пера рендерятся через `paintBrushStroke`; ластик имеет отдельную операцию `destination-out`.
- R2 `transformItems` сейчас переписывает точки с сохранением `x,y`, но без дополнительных полей: эту ветку нужно обновить вместе с форматом.
- IndexedDB хранит редактируемый проект; v1-черновики уже мигрируют через `createProject`. Важно не сделать прежние v2-проекты нечитаемыми.

Спецификация Pointer Events Level 3: https://www.w3.org/TR/pointerevents3/. `pressure`, `tiltX`, `tiltY`, coalesced events доступны как свойства событий; значения могут быть аппаратно эмулированы или отсутствовать. Наличие поля **не означает** аппаратную чувствительность к нажиму.

## 4. Проект данных и миграций

1. Ввести отдельный `StrokePoint`, расширяющий координаты опциональными `pressure?: number`, `tiltX?: number`, `tiltY?: number`. Не добавлять поля давления в точки фигур, заливки или панорамирования.
2. Для новых штрихов пера фиксировать нормализованный нажим в пределах `[0,1]`, углы наклона в пределах `[-90,90]` градусов; недостоверные/отсутствующие значения не должны попадать в сохранённый документ как `NaN`, `Infinity` или неконтролируемые числа.
3. Добавить снимок настроек в `Stroke`, например `dynamics?: { pressureSize: number; tiltAngle: boolean }`, где `pressureSize` в `[0,1]`. Настройки фиксируются **при начале штриха**: изменение UI позже не меняет старую линию.
4. Поднять схему документа до `3`; `parseDrawingProject` должен читать **v2 и v3**, возвращая нормализованную v3-модель. Миграция v2 сохраняет исходные штрихи без динамики, порядок операций R2, слой-референс, палитру, учебные метаданные и идентификаторы.
5. Старые штрихи без `dynamics` должны рисоваться **прежним алгоритмом и с прежними пикселями**. Миграция не должна пересоздавать графику и менять ширину.
6. `copyStroke`, модельные команды, R2 `transformItems`, история и сериализация сохраняют динамические поля всех затронутых точек. Трансформация меняет только координаты и существующую общую ширину штриха; не перезаписывает нажим или наклон.
7. Валидация хранимого документа должна отвергать некорректные значения полей динамики; импорт старой v2-модели должен проходить без утраты данных. Не увеличивать прежний лимит 16 слоёв, размер холста 4096² и лимит семплов кисти без отдельного бенчмарка.

## 5. Получение ввода

- Снимать `pointerType`, `pressure`, `tiltX`, `tiltY` с исходного и коалесцированных событий одного `pointerId`, сохраняя порядок, исключая чужой указатель.
- На мыши и пальце **не активировать** перьевую динамику: нынешние кисти остаются визуально и функционально прежними.
- Для `pointerType = pen` корректно обрабатывать нулевое/неизменяющееся/эмулированное `pressure`: не рисовать исчезающую линию и не считать такие события доказательством аппаратной поддержки.
- При одинаковых координатах и изменившемся нажиме обновлять атрибуты последнего образца, а не безгранично добавлять дубликаты. Коалесцированные пакеты должны оставаться ограниченными.
- Продолжать действующие правила захвата указателя, отмены жеста, подавления ладони и двухпальцевого зума. При выходе из холста, `pointercancel` и `lostpointercapture` не сохранять повреждённый штрих.
- Для неопознанного `pointerType` использовать нынешний путь без динамики. Нельзя заявлять, что каждый браузер передаёт реальный нажим/наклон.

## 6. Выразительная линия в R3A

- Изменять толщину по нажиму **только** у существующих `pencil` и `liner`; `calligraphy` получает изменение толщины по нажиму и ориентации широкого пера по наклону. Остальные 7 пресетов, а также ластик и фигуры, в этом PR сохраняют старый рендер.
- Для динамических штрихов использовать детерминированную интерполяцию нажима между соседними точками и ограниченный по объёму семплинг. Предложенная функция толщины: `baseWidth × (1 + pressureSize × (pressure − 0.5))`, с безопасным нижним пределом; при `pressure = 0.5` толщина равна существующей.
- Каллиграфическая ориентация: при осмысленном `tiltX/tiltY` угол широкого пера следует направлению наклона; при отсутствующем наклоне сохраняется нынешний фиксированный угол `−π/4`. Точная конверсия осей — ответственность реализации, но должна быть чистой тестируемой функцией.
- Preview и окончательный рендер должны использовать общий код, чтобы при отпускании пера линия не «прыгала». Отрисовка одной и той же истории после save/reload/export должна быть детерминированной.
- Ластик не обязан реагировать на нажим на первом срезе, но не должен ломаться рядом с динамическими штрихами. Маски и blend modes в R3A не добавлять.

## 7. UI, режимы, доступность

- В существующей компактной зоне параметров кисти добавить настройки **«Нажим»** (чувствительность 0–100%) и **«Наклон пера»** (включён/выключен для каллиграфии). Без новой постоянной боковой панели и без изменений цветовой палитры, типографики и общего расположения холста.
- **Предлагаемые начальные настройки:** чувствительность `80%` и наклон `включён`. Эффект применяется только к новым штрихам, начатым пером. Ноль процентов явно отключает изменение ширины, выключенный наклон оставляет фиксированную ориентацию каллиграфического пера.
- **Предлагаемая область действия:** одна чувствительность для трёх поддерживаемых кистей, сохранение выбора при переключении между ними в течение открытой сессии; настройки живут в состоянии редактора, как текущая ширина кисти, и не требуют отдельного долговременного хранилища в R3A. При повторном открытии редактора используются значения по умолчанию; ранее сделанные штрихи сохраняют собственные параметры в документе.
- В свободном редакторе доступно сразу, без проверки прогресса. В уроке не обходить `Tool Access Policy`; при наличии разрешённого инструмента перьевой ввод работает, но учебные ограничения сохраняются.
- Для мыши/касания старые штрихи отображаются одинаково независимо от положения этих настроек. Понятная подпись объясняет, что эффект доступен при передаче данных стилусом.
- Сохранять управление с клавиатуры, не уменьшать сенсорные зоны и не создавать горизонтальную прокрутку на планшете/телефоне. Не менять загрузку или масштабирование референса.

## 8. Проверки и критерии приёмки

### Автоматические release gates

1. Unit: захват `pressure`/`tilt` из коалесцированных событий; некорректные/пустые значения и чужие `pointerId`; постоянные координаты при изменяющемся нажиме; touch/mouse без динамики.
2. Unit модели: v2 → v3 миграция без потерь, v3 round-trip, отказ от некорректной динамики, трансформация R2 сохраняет свойства пера, undo/redo, доступ к уроку.
3. Рендер: динамическая толщина действительно различается на низком/высоком нажиме, изменение наклона влияет на каллиграфию; результат детерминированный и совпадает в preview/export; наследуемый v2-штрих пиксельно не отличается от R2.
4. IndexedDB: открыть v2, добавить перьевой штрих, отменить/повторить, сохранить, перезагрузить и экспортировать PNG; прежние рисунки остаются редактируемыми.
5. Browser E2E Chromium: синтетический stylus pointer stream, zoom/pan, отмена жеста, touch/mouse fallback, мобильная панель и регрессия импорта референса.
6. Реальные команды проверки из `apps/web`: typecheck, unit, build, browser tests, `git diff --check`. Приложить логи, точное количество PASS/FAIL и хэш коммита; не ссылаться на один общий статус без артефактов.

### Аппаратный gate — отдельно

- Ручная матрица: модель Huawei, версия ОС, Яндекс Браузер, модель пера; отображаются ли реальные изменения `pressure/tilt`; рисование, касание ладонью, двухпальцевое масштабирование, импорт PNG/JPEG/WebP и восстановление работы.
- Проверка также на документе `2048×2048` с восемью слоями и в сеансе **не менее 15 минут** с записью задержек, ошибок памяти, непредвиденных отмен и пропусков штрихов. Порог производительности для публичного релиза нужно определить по результатам базовых измерений на конкретном устройстве, а не придумывать до аппаратного прогона.
- Исполнитель физической проверки — владелец планшета с доступом к совместимому перу либо отдельно привлечённый тестировщик; автор кода не может заявить прохождение проверки по одному синтетическому прогону.
- Пока нет физического прогона, статус **`NOT TESTED`**, а не `PASS`. Успешный Playwright **не** подменяет аппаратную приёмку.

## 9. Ограничения поставки

- R3A — отдельная ветка и Draft PR поверх R2, без merge в `main` и без выкладки на сайт на основании только синтетических тестов.
- Текущие учебные маршруты, цвета, шрифты, референсы, история и локальные данные не изменяются по смыслу.
- Не подключать OpenAI API, внешние сервисы, серверы или аналитику; файлы рисунков остаются локальными.
- Если модельная миграция или обработка образцов требует большого изменения `EditorCanvas`, сначала доказать минимальность изменения тестами и локальным профилем, а не переписывать весь движок.
